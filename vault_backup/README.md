Роль vault_backup создает снапшот через vault operator raft snapshot save, добавляет крон-задание на снятие бэкапа бд раз в сутки и его загрузку в указанный s3 бакет.
Так же роль проверяет наличие AWS ClI и при отсутствии устанавливает.
Перед раскаткой роли необходимо задавать переменные для доступа к бакету, vault токен и пароль alertmanager (при alertmanager_basic_auth_enabled == true).

Роли задается retention_policy хранения бэкапов в бакете и локально. По умолчанию переменная равна 7, метод retention - full backup
```
retention_policy
```

```
vault_token: "vault_token"
s3_bucket: "s3_bucket"
s3_path: "dir/dir"

```

Также добавляет проверку наличия бэкапов за последние 2 дня локально и в облачном хранилище.
Запускать роль необходимо на vault хост с сконфигурированным raft кластером и подключенными пирами.
```
alertmanager_basic_auth_enabled: false
```
В group_vars/vault.yml задается хост и порт для доступа к API Vault, настройки подключения к alertmanager (url, user) и s3 бакету.
Если необходимо сменить настройки кронов или дефолтные настройки, то это задается в дефолтных переменных роли.

При отсутствии архивов или расхождении размеров архивов более, чем на 5%, отправляются алерты с соответствующим названием в alertmanager, которые будут существовать 2 дня с момента алерта или до момента их резолва при следующем снятии бэкапа.
При фейле бэкапа отправляется алерт с соответствующим названием в alertmanager, который будет существовать 2 дня с момента алерта или до следующего успешного снятия бэкапа.
